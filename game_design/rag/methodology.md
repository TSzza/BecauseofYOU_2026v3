# Designer RAG：五个月版使用说明

## 核心原则

- 本资料模仿原表的设计方法，不复制原事件：世界约束、立体人物、事件链和简短行为选项共同构成生成骨架。
- 时间严格限制在九月、十月、十一月、十二月和次年一月寒假。人物只发生小而可观察的变化。
- Designer 每局先判断需要覆盖的人物线、月份节点、关系网络与行为证据，再自主决定总回合数；代码只校验范围与一致性。
- 事件库是可检索素材，不是必须按序播放的固定剧本。可以改写场景措辞和细节，但不得破坏月份、前置依赖、人物核心和现实边界。

## 事件装配

1. 每局选择 4–7 名 NPC，至少覆盖同桌/寝室/学习或社团中的三类关系。
2. 五个月均至少安排一个回合。九月偏相识，十月至十二月展开个人或双人事件，一月负责期末与寒假收束。
3. 选择后续事件前必须包含其前置事件；无法满足前置时，换用无依赖事件，不得虚构玩家已经经历。
4. 收束事件只总结本局实际发生的细节，不宣称角色被玩家“治愈”或彻底改变。
5. 选项使用短行为表达。后果描写即时关系、情绪、策略或边界变化，不把单次选择映射成疾病、人格标签或确定结论。

## 动态回合策略

Designer 根据人物数量、依赖链长度、五个月覆盖和节奏决定 10–26 个回合。每个种子允许不同总数；不得把示例事件数或月份数直接当作固定回合数。单局通常只取事件库的一部分，并允许插入少量符合约束的日常过渡事件。

## 质量检查

- 月份是否完整且按时间递增；寒假事件只能在一月阶段。
- 所有 NPC ID 是否存在；动态群像事件只引用本局已建立关系的人物。
- 所有前置是否在时间线上更早出现；没有循环依赖。
- 对话是否具有角色辨识度，是否避免人人温柔、人人善解人意。
- 冲突是否保持普通校园尺度，选择是否都具有合理代价。
- 测量只基于跨情境行为证据，禁止临床诊断和单点定性。
